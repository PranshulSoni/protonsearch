## 1. Core Philosophy: The Living Interface

An interface feels alive when motion begins from the current on-screen presentation value, inherits the user velocity, projects momentum forward, and remains interruptible at every frame.

Apple defines design around four fundamental human needs:
1. **Safety and Predictability**: Interfaces must behave consistently so users never fear making an error.
2. **Understanding**: Visual hierarchy, spatial continuity, and translucency explain state transitions without words.
3. **Achievement**: Latency elimination ensures the tool amplifies intention rather than impeding execution.
4. **Joy**: Natural physical physics and calibrated spring damping transform routine interactions into tactile satisfaction.

```
Direct Input -> Zero Latency -> Physical Springs -> Spatial Continuity -> Predictable Settle
```

## 2. The Apple Spring Physics Framework

CSS transitions with fixed duration curves (like linear or ease-in-out) create artificial computer motion. They cannot accept incoming pointer velocity, cannot be redirected mid-motion without velocity discontinuities, and feel detached from physical touch.

ProtonDock replaces arbitrary transition durations with Apple two-parameter spring dynamics:
- **Damping Ratio (\(\zeta\))**: Controls overshoot and bounce.
  - \(\zeta = 1.0\) (Critically Damped): Zero bounce, non-distracting, smooth settle. Used for standard UI layout transitions, dock expansion, and profile switches.
  - \(\zeta \approx 0.8\) (Under-damped): Gentle physical bounce. Used only when an interaction carries momentum (flick, release, drag handoff).
- **Response Time (\(T_r\))**: How rapidly the spring reaches its target, measured in seconds. This is not a fixed duration; the settling time naturally emerges from boundary displacement and initial velocity.

### Spring Parameter Reference Table

| Interaction Context | Damping Ratio (\(\zeta\)) | Response Time (\(T_r\)) | CSS Approximation Curve | Behavior |
| :--- | :--- | :--- | :--- | :--- |
| **Dock Rail Width Morphing** | `1.0` | `0.38s` | `cubic-bezier(0.16, 1, 0.3, 1)` | Smooth expansion without horizontal overshoot |
| **Widget Reorder / FLIP** | `1.0` | `0.32s` | `cubic-bezier(0.16, 1, 0.3, 1)` | Instant displacement handoff, zero layout stutter |
| **Widget Size Expansion** | `1.0` | `0.35s` | `cubic-bezier(0.16, 1, 0.3, 1)` | Width glides smoothly; height locked at 48px |
| **Popover Scale & Origin** | `0.82` | `0.30s` | `cubic-bezier(0.25, 1, 0.35, 1)` | Tactile spring entry anchored from widget trigger |
| **Active Tile Pointer-Down**| `1.0` | `0.10s` | `ease-out` | Instant response on pointer-down: `scale(0.96)` |
| **Profile Switch Transition**| `1.0` | `0.40s` | `cubic-bezier(0.16, 1, 0.3, 1)` | Unified rail morph with staggered widget glide |

## 3. Geometry and Sizing Invariants

### 3.1 Locked Square Height Invariant
ProtonDock enforces an absolute height contract:
- **Height Token**: `--tile-h: 48px;`
- **Rail Height**: `calc(var(--tile-h) + var(--dock-pad) * 2)` (60px total with 6px padding)
- **Invariant Guarantee**: Every widget, regardless of display mode, expansion state, or active profile, maintains an exact 48px height. No animation or interaction is permitted to alter widget height.
- **Discrete App Slots (No Multi-App Capsules)**: Every running application and pinned application renders strictly as an independent 48px square tile directly on the dock rail. Grouping apps into wide capsules or cramped sub-clusters is prohibited.

### 3.2 Icon Sharpness & Sizing Contract
- **Small Centered Glyph**: Inside the 48px square tile, application and widget icons must be small: `20px x 20px` to `22px x 22px` (never exceeding `24px x 24px`), centered within a `32px x 32px` glyph box with `13px` to `14px` optical margin.
- **High-DPI Extraction**: Extract 256x256 uncompressed icons from Windows `SHIL_JUMBO` and downsample via Lanczos3 filtering with an unsharp mask in the backend. Low-res 32x32 or 16x16 icon extraction is banned to eliminate blurry icons.
- **Frontend Anti-Blur**: Apply `image-rendering: -webkit-optimize-contrast;`, `shape-rendering="geometricPrecision"`, and `transform: translateZ(0)` to eliminate subpixel GPU blur.

### 3.2 Discrete Width Steps
Horizontal scaling follows disciplined discrete increments:
1. **Square Tile (Default)**: `48px` width (1:1 aspect ratio).
2. **Compact Rectangle**: `96px` width (2:1 aspect ratio).
3. **Standard Rectangle**: `140px` width (balanced title + sub-label stack).
4. **Wide Rectangle**: `168px` width (now playing scrubbers, running app clusters).

### 3.3 Continuous Squircle Corners
Corners use Apple continuous curvature (superellipse \(n \approx 4\)) rather than standard circular arcs:
- Dock Rail Radius: `var(--dock-radius: 20px)`
- Widget Tile Radius: `var(--tile-radius: 12px)`
- Pill Buttons Radius: `999px`

## 4. Multi-Profile Engine & Fluid Dock Morphing

### 4.1 Built-in and Custom Profiles
ProtonDock ships four curated system profiles, with full runtime support for user-defined profiles:
- **Daily**: Minimal high-contrast everyday setup (`start`, `search`, `running-apps`, `siri-ai`, `claude`, `codex`, `music-player`, `clock`).
- **Work**: Full productive workstation dock with live battery telemetry, Wi-Fi, Bluetooth, system tray, and notifications.
- **Founder**: AI-forward executive cockpit with dual model usage rings, pinned repos, and quick note capture.
- **Focus**: Zen flow layout containing solely Start, Kensaku Search, Clock, Quick Jot Notes, and Spotify.
- **User Custom Profiles**: Created natively via the top-shelf `+` trigger or customizer modal. Persisted directly in local storage with custom widget selections and width settings.

### 4.2 FLIP Morphing Pipeline
When switching profiles or resizing widgets, ProtonDock executes a First-Last-Invert-Play (FLIP) sequence:
1. **First**: Record bounding client rects of the dock rail and all active widget slots.
2. **Mutate**: Apply the target profile state to the DOM.
3. **Last**: Measure target client rects of the expanded/contracted dock rail and slots.
4. **Invert**: Calculate horizontal displacement \(\Delta x = \text{rect}_{\text{first}}.left - \text{rect}_{\text{last}}.left\) and width delta \(\Delta w\).
5. **Play**: Animate the dock rail width and widget transforms using the Apple spring curve `cubic-bezier(0.16, 1, 0.3, 1)`.

```javascript
// Dock Rail FLIP Spring Expansion
const deltaWidth = lastWidth - firstWidth;
if (Math.abs(deltaWidth) > 0.5) {
  dockRail.style.width = firstWidth + 'px';
  dockRail.offsetHeight; // Force layout reflow
  dockRail.style.transition = 'width 380ms cubic-bezier(0.16, 1, 0.3, 1)';
  dockRail.style.width = lastWidth + 'px';
}
```

## 5. In-Place Widget Resizing & Edit Mode

### 5.1 Pristine Normal State vs Explicit Edit Mode
- **Pristine Normal State**: In default operation, the dock is completely uncluttered. Zero hover navigation arrows, zero expand buttons, and zero dragging affordances are visible or active. Clicking any widget instantly opens its anchored popover or launches its application without layout displacement.
- **Explicit Edit Mode**: Only when the user explicitly clicks the shelf `Edit` button does edit mode activate:
  1. The Edit button morphs into a high-contrast `Done` button with a checkmark.
  2. Slots become draggable (`draggable="true"` with `cursor: grab`) enabling 1:1 direct manipulation reordering.
  3. Discrete Apple-style resize chips (`.dw-resize-chip`) appear at the top-right corner of each widget.
  4. Clicking any widget or its resize chip smoothly cycles its width (`48px` -> `96px` -> `140px` -> `168px` -> `48px`) using Apple spring dynamics.
  5. Neighboring widgets glide horizontally via FLIP transitions to accommodate width shifts; height remains strictly locked at 48px.
  6. Clicking `Done` or pressing `Escape` exits edit mode, locks the layout, and synchronizes custom widths to local storage.

## 6. Materials, Optical Blur, & Three Native Themes

Depth in ProtonDock is communicated through physical materials rather than arbitrary flat colors:

### 6.1 Theme Matrix

| Theme | Material Token | Surface Color | Specular Reflection | Backdrop Filter |
| :--- | :--- | :--- | :--- | :--- |
| **Dark** | Slate Charcoal Glass | `rgba(14, 18, 26, 0.94)` | `inset 0 1px 0 rgba(255, 255, 255, 0.10)` | `blur(28px) saturate(140%)` |
| **Light** | Frosted Alabaster Glass | `rgba(250, 252, 255, 0.96)` | `inset 0 1px 0 rgba(255, 255, 255, 0.80)` | `blur(28px) saturate(150%)` |
| **Liquid Glass** | Tahoe Liquid Refraction | `rgba(255, 255, 255, 0.10)` | `inset 0 1.5px 0 rgba(255, 255, 255, 0.65)` | `blur(48px) saturate(220%)` |

### 6.2 Translucency Hierarchy
- **Level 1 (Dock Rail Chrome)**: Thick translucent boundary containing and grounding all controls.
- **Level 2 (Widget Capsules)**: Subtle interactive surfaces that glow on hover (`rgba(255, 255, 255, 0.08)`).
- **Level 3 (Anchored Popovers)**: Elevated glass cards casting deep spatial ambient shadows (`0 24px 60px rgba(0, 0, 0, 0.65)`).
- **Specular Edge**: A 1px top highlight catches ambient light at the upper boundary of every glass surface, grounding the perception of physical glass.

## 7. Typography and Optical Tracking

Typography is tuned to optical size rules:
- **Display and Headings**: Negative tracking (`letter-spacing: -0.02em`) pulls large glyphs together into cohesive units.
- **Micro-labels and Badges (9px to 11px)**: Positive tracking (`letter-spacing: 0.03em` to `0.05em`) ensures small capitals remain legible against frosted glass.
- **Monospace Code and Telemetry**: `ui-monospace, SFMono-Regular, Menlo, monospace` for tabular numbers and wattage readouts, preventing character jitter during live updates.

## 8. Accessibility & Reduced Motion

- **`prefers-reduced-motion: reduce`**: Disables FLIP spring transitions and replaces width animations with instant layout updates and soft 120ms opacity cross-fades.
- **`prefers-reduced-transparency: reduce`**: Replaces backdrop filters with solid opaque surfaces (`#0c1017` dark, `#ffffff` light) and 1.5px high-contrast borders.
- **High Contrast**: Text contrast ratios exceed 12:1 across all active elements, surpassing WCAG AAA requirements.

## 9. CoolDock & Docktor Live Telemetry Widgets Design Standards

1. **Information Density without Clutter**:
   - Live widgets prioritize glanceable high-signal numbers over decorative flourishes.
   - Secondary metrics use reduced opacity (`rgba(255, 255, 255, 0.6)`) and optical tabular spacing so numbers do not jump or twitch during real-time data updates.
2. **Sparkline and Gradient Fill Principles**:
   - Telemetry curves use smooth cubic bezier interpolation between historical data points.
   - The area under the sparkline curve is filled with a vertical linear gradient fading to full transparency at the bottom, creating luminous depth without visual weight.
   - Peak markers and current value indicators use high-contrast accent dots (`#34d399` and `#38bdf8`) with micro-typography positioned to avoid clipping.
3. **Apple Calendar Crimson Card**:
   - Modeled after the iconic macOS Calendar icon: a rich crimson gradient (`#e11d48` to `#be123c`) with an inset highlight and subtle shadow.
   - Upper abbreviation in tracking `0.06em` white capital letters, lower date in bold proportional numerals.
4. **Direct Media Transport Controls**:
   - Buttons (`<<`, `||`/`▶`, `>>`) provide instant hover states and tactile press feedback (`scale(0.92)`).
   - Album artwork thumbnails feature continuous squircle corners (`6px`) and gentle ambient drop shadows to stand out against translucent glass rails.

## 10. Ganella In-Place Manipulation & Agent Motion Standards

1. **Alt-Click (Option-Click) Direct Manipulation**:
   - Holding `Alt` while clicking any dock slot triggers instant in-place morphing between its 48px square state and its expanded live capsule state.
   - Motion is driven by the Apple spring curve `cubic-bezier(0.16, 1, 0.3, 1)` with `0.38s` response time. Sibling slots glide sideways using FLIP transforms without layout flicker.
2. **AI Agent Live Activity Dynamics**:
   - When an AI agent executes tasks or streams completions, the ring glyph transitions into an active revolving halo (`1.4s` linear infinite rotation with a soft ambient glow).
   - Once execution finishes, the halo settles smoothly into its resting state, displaying quota or connectivity metrics.
3. **Calendar Week Strip Spatial Rhythm**:
   - The weekly schedule strip arranges seven day columns with balanced optical spacing (`6px 8px` container padding).
   - Today's column is highlighted with an Apple-style crimson gradient card (`#e11d48` to `#be123c`) and white numerals. Event presence is communicated with crisp `3.5px` dot markers.
