PROTON / PRODUCT & ENGINEERINGBRANCH 2.0.0 · PROPOSAL
04 / WINDOWS INTEGRATION

Respect the desktop contract.

A good dock is easy to personalize. A dependable replacement is difficult to break.

Two operating modes

DEFAULT · FIRST RELEASE PATH

Coexistence

Explorer and its taskbar remain available. Proton registers its own AppBar, negotiates work area, and behaves correctly with other bars. User may use Windows' own auto-hide setting.

EXPERIMENTAL · SEPARATE GATE

Replacement appearance

Explorer continues running. An explicit user action enables a reversible taskbar visibility adapter on tested builds. Native tray access and recovery are mandatory. This is not a shell replacement.

The documented AppBar mechanism reserves edge space and cooperates with other bars. It does not make Proton the supported successor to Explorer's Start, tray or notification host. Hiding taskbar windows is a compatibility technique; do not present it as a guaranteed Windows extension contract. [S01]

Keep notification center, input/language switching, Task View, accessibility entry points and secure desktop available through native routes. Jump lists, drag-to-open, window thumbnails, progress overlays and notification mirroring need separate taskbar-parity fixtures before claiming completeness.

Tray is its own project

Shell_NotifyIcon documents how an application publishes its icons to the status area. It does not supply a general public enumeration-and-hosting API for all other apps' tray icons. A native-tray access widget can satisfy availability initially; it must clearly say it opens the native surface. Complete migration of third-party tray icons is an unproven capability, not a small icon-rendering task. [S07]

Recovery state machine

Coexisting → PreparingReplacement → ReplacementActive
                  ↓ failure             ↓ heartbeat lost / Explorer restart
              RestoreNative ← Restoring ←───────────────┘
                  ↓
           Coexisting / SafeMode
  1. Validate current session, tested Windows build, native-tray fallback and watchdog readiness.
  2. Persist a journal of only OS state Proton will change. Include owner/session, generation, before-state and expiry; use atomic replace.
  3. Watchdog independently observes UI heartbeat (candidate: every 500 ms; recover after 3 seconds unresponsive). It must be able to restore without loading plugins or main databases.
  4. Apply visibility change only after journal flush and heartbeat handshake. Avoid global registry mutations and killing Explorer.
  5. On crash, hang, update, uninstall, explicit quit, emergency shortcut or compatibility mismatch: restore native taskbar first, release AppBar, then exit/relaunch.
  6. After repeated crash (candidate: 3 within 60 seconds), disable replacement on next start and enter safe mode. If recovery cannot be guaranteed on a build, do not enable hiding there.

A watchdog can also fail. Startup recovery from stale journal and a standalone restore command are required; both must work from Task Manager/Run without the dock. Journal restoration is ownership-aware: do not overwrite taskbar settings the user changed after the snapshot. Test the actual adapter; the state machine alone proves nothing.

Ship gates

  • No inaccessible native tray, language/input, network or security workflow.
  • Crash/hang injection restores native taskbar within the recovery target on every tested build.
  • Explorer restart during replacement returns to coexistence first; re-enable only after validation.
  • Display disconnect, DPI change, fullscreen and RDP cannot leave an invisible input-blocking window.
  • Upgrade/uninstall restore shell state before changing files; data is preserved by default.
  • No Explorer injection, undocumented message dependency or Windows-key hook in the stable critical path.
