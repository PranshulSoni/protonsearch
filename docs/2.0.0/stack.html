03 / TECH STACK & DECISIONS

Choose for the resident surface.

A framework choice must survive real Windows behavior, memory measurements and assistive technology.

Recommended starting pointRust + windows-rs + Slint for the native dock, SQLite FTS5 for search. Provisional until renderer and integration spikes pass.
OptionWhy consider itTradeoffDecision
Rust + SlintExisting dependency/settings experience; direct Rust integration; native rendered resident surfaceCustom desktop behaviors, editor widgets, accessibility and public SDK licensing need proofFirst candidate

C# + WPF / Windows App SDKStrong Windows tooling, mature desktop controls and UI Automation; interop with Rust servicesTwo language/runtime boundaries and launcher rewrite cost; custom UI still needs designNative accessibility fallback if both Rust UI options fail
C++ + Qt QuickMature UI toolkit and Windows accessC++/Rust FFI ownership, deployment and license review add complexityReserve for demonstrated need

Hand-written Win32/GDI throughoutCurrent launcher knowledge; direct controlExisting giant UI module demonstrates maintenance and customization costUse at platform boundaries, avoid as new widget UI framework

These are engineering judgments, not benchmark rankings. Tauri uses the platform webview on Windows; smaller installer size does not establish lower resident memory. Capabilities must be configured and custom commands protected explicitly. [S08] [S09]

Renderer selection experiment

  1. Build the same 10-widget dock in Slint and Tauri: Start, Search, Agents, apps, files, weather, audio, battery, tray access and clock. Same sample feed, assets, monitor setup and animations.
  2. Measure idle private bytes and working set for the entire process tree, CPU, wakeups, startup, warm open and p95 frame time on an integrated-GPU laptop.
  3. Exercise AppBar registration, HWND ownership/subclass cleanup, nonactivating dock vs activating flyouts, hit testing, mixed DPI, Narrator and high contrast.
  4. Choose Slint if it passes all hard gates. Prefer Tauri if Slint fails a blocker and Tauri passes the same gates within agreed budgets. If neither passes, evaluate a WPF host around Rust services.
  5. Record measurements and pin versions in ADR-001. Do not build two permanent UIs.

Licensing gate

The repository is MIT; that does not make Slint or every asset MIT. Slint offers licensing choices. Its royalty-free agreement includes attribution conditions and a restriction on exposing Slint APIs. A public arbitrary .slint widget SDK therefore needs vendor/legal clarification. A renderer-neutral Proton schema is the proposed boundary, not a guaranteed legal workaround. Confirm distribution terms before renderer lock and public SDK release. [S10]

Decision records to keep

  • ADR-001: renderer benchmark and license choice.
  • ADR-002: coexistence default and taskbar compatibility support matrix.
  • ADR-003: renderer-neutral widget contract and trust tiers.
  • ADR-004: user-data split, preview identity and migration ledger.
  • ADR-005: capability broker and agent execution boundary.
  • ADR-006: update signing, rollback and rebrand transition.

No new runtime dependencies are added by this plan. Exact releases must be checked at implementation kickoff; this document avoids speculative “latest version” pins.
