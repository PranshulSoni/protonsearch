05 / WIDGET PLATFORM

One contract. Many expressions.

Make it easy to build useful widgets without letting a widget own the desktop.

Four distinct objects

ObjectPurpose
DefinitionPackage identity, API version, supported sizes, configuration schema, permissions and view templates
InstanceA user's placement/configuration of a definition; multiple weather cities are separate instances
ProviderHost data service such as audio, battery, weather or agent state; shared among instances
ViewValidated renderer-neutral tree for tile and panel; host owns layout, input, accessibility and rendering

Illustrative manifest

{
  "schema_version": 1,
  "id": "proton.weather",
  "version": "0.1.0",
  "api": "^1",
  "sizes": ["compact", "wide", "rich"],
  "views": {"tile": "weather.tile.json", "panel": "weather.panel.json"},
  "permissions": ["weather.read"],
  "config_schema": {
    "type": "object",
    "required": ["location_ref"],
    "properties": {"location_ref": {"type": "string", "maxLength": 128}},
    "additionalProperties": false
  }
}

This manifest is a proposed example, not an implemented SDK or formal schema. weather.read uses the host weather broker; the widget receives no generic network permission. Version matching, signature verification and configuration validation occur before activation.

Lifecycle

discover → validate → install → configure → mount → subscribe
                                                 ↕
                                            suspend/resume
                                                 ↓
                                unmount → release → uninstall

Separate definition version, instance revision and runtime session. Configuration saves are transactional. Resource leases close on unmount; no orphan timers. Every state has loading, stale, offline, unsupported, permission-denied and crashed representations. Timed-out providers cannot block layout. Visibility can pause presentation without deleting shared state or an agent job.

Rendering constraints

  • Initial DSL: Row, Column, Text, Icon, Badge, Progress, Sparkline, Button, Toggle and Slider. No HTML, arbitrary script, shader or raw Slint binding in dock packages.
  • Host validates depth, node count, text length, image dimensions and update rate. Candidate caps: 128 tile nodes, 512 panel nodes; tune with measurements.
  • Labels, roles, focus order and accessible values are mandatory. Host owns semantic accessibility mapping.
  • Actions reference typed host commands such as panel.open, audio.set_volume and search.open. No raw command strings or arbitrary URLs.
  • Width changes happen only through explicit size changes. Numbers truncate predictably, charts use bounded buffers, no layout jitter from polling.
  • One active transient panel per dock; detached persistent panels are a later feature. No panel can cover recovery controls.

Wasmtime can bound guest execution using fuel/epoch interruption, but synchronous host calls need their own deadlines and resource limits. Broker network/filesystem requests explicitly; Wasm does not make authorized host functions safe by itself. [S11]

Profiles and layout

{
  "schema_version": 1, "id": "work", "revision": 3,
  "display_layouts": [{
    "display_ref": "primary", "edge": "bottom", "scale": 1.0,
    "items": [
      {"instance_id": "start-work", "definition": "proton.start", "size": "compact"},
      {"instance_id": "weather-work", "definition": "proton.weather", "size": "wide"}
    ]
  }],
  "privacy": {"hide_sensitive_previews": false}
}

A layout switch is an atomic change of visible instance references. Do not duplicate active agent runs or re-request authority. Keep dormant instance state and monitor mappings. If width is insufficient, first shrink only widgets that opt into automatic sizing, then move low-priority items into an overflow drawer. Critical host recovery remains accessible outside that list.

Weather provider decision

Start with manual city selection and brokered cached requests; precise geolocation is optional consent. Open-Meteo is a candidate, but its free API has non-commercial terms and attribution requirements. Choose a suitable paid/provider agreement if commercial distribution requires it; expose provider licensing and data provenance in settings. Never imply “free forever” for an eventual commercial app. [S12]

Ecosystem roadmap

Ship excellent first-party widgets first. Next publish a versioned schema, validator, examples and compatibility tests. Then accept curated declarative packages with provenance, digests, review and rollback. Add sandboxed logic only after quota and adversarial tests. Marketplace accounts, payments and hundreds of packages follow demonstrated developer demand; no cloud backend is needed for the first release.
