Migration blockers

Uninstall deletes data

installer.iss:31–33 removes the entire current AppData directory. Preview must have separate install/data identity; fix preserve-data behavior before side-by-side release.

Global approval state

ai.rs:10 and main.rs:2357,3341 expose global always-approve behavior. New jobs and widgets must receive explicit scoped grants, never inherited blanket trust.

  • Paths: live data mixes personal state and rebuildable index in %APPDATA%\protonsearch\file_index.db. settings.rs:192–223 also considers executable-directory settings.
  • Schema: initialization is spread through search.rs, indexer.rs, main.rs and settings_ui.rs. Audit actual tables; introduce ordered migrations and a schema ledger.
  • Legacy rename: main.rs:732–740 conditionally renames OmniSearch data only when the new path is absent; handle both-path conflicts explicitly.
  • Secrets: plaintext storage/CLI transfer paths and a fixed Hermes fallback key require remediation before exposing third-party execution.
  • Version drift: package, installer, update feed and settings default say 1.1.0 although the prior branch is 1.1.1. Branch naming is not a release/version bump.

Import and rollback transaction

  1. Detect source locations and versions read-only. Show what will be imported and conflicts. Acquire a migration lock; stop or coordinate source writes.
  2. Make a consistent SQLite backup through the backup API, plus settings, clipboard images and other user artifacts; handle WAL correctly. Never copy only a live .db.
  3. Import into separate preview storage. Separate notes/pins/chats/settings from rebuildable index; migrate secrets into Windows credential storage without exporting them.
  4. Run ordered transactional migrations and validate row counts, integrity, foreign keys and representative query fixtures.
  5. Mark import complete atomically. Retry is idempotent; interrupted import leaves v1 untouched.
  6. Rollback by stopping preview and returning to original app/data. Do not reverse unknown schema writes into v1. Uninstall preview preserves personal state unless user explicitly chooses deletion.

Recommended extraction order

Domain/actions → app paths/storage → search façade → platform providers → new dock consumer → widget composition → agent scheduler. Keep existing executable usable until the dock reaches parity. Fast/slow search result phases and document extraction isolation are assets to preserve.

Rebrand checklist for a later decision

Repository URL, installer AppId, executable/process, window class and single-instance IDs, startup registration, data identity, update trust prefix, signing identity, winget package, icons and attribution all need a coordinated migration. settings_ui.rs:40–42 hardcodes the trusted update repository prefix; a repo rename requires an updater transition. Do not casually change paths to match a new product name.
